## 2026-10-16 - Rate Limiter DoS & Bypass Vulnerabilities
**Vulnerability:** The in-memory map rate limiters used `map.clear()` when reaching capacity, which allowed an attacker to bypass all rate limits globally by overflowing the map. Other endpoints pruned old entries but failed to enforce a strict upper bound if all 5000 requests occurred recently, leading to an unbounded O(N) map and potential CPU/Memory exhaustion DoS.
**Learning:** Using `map.clear()` is highly dangerous for rate limiters as it resets protections for all IPs. Relying solely on time-based pruning isn't enough to prevent DoS if traffic spikes rapidly.
**Prevention:** When an in-memory map rate limiter reaches capacity, always selectively prune expired entries. If the map still remains full, enforce a strict upper bound by forcibly evicting the oldest entries (using `map.keys().next().value`) to prevent memory exhaustion and DoS.
