## 2025-02-18 - [CRITICAL] Telegram Webhook Authentication Bypass
**Vulnerability:** The Telegram webhook (`/api/telegram/webhook/route.ts`) verified requests by falling back to checking if the user-controlled JSON payload (`update?.callback_query?.message?.chat?.id`) matched an authorized `TELEGRAM_CHAT_ID` if the `TELEGRAM_WEBHOOK_SECRET` was missing or mismatched. Because webhooks are publicly accessible, an attacker could spoof this JSON payload to bypass authentication completely and update order states (e.g., mark as paid or cancelled).
**Learning:** Never use data from a user-supplied JSON payload as a fallback authentication mechanism for webhooks. Secrets should be enforced strictly.
**Prevention:** Always rely strictly on cryptographically secure tokens (like `x-telegram-bot-api-secret-token`) sent in headers and verified with a constant-time comparison (`timingSafeEqual`) to authenticate webhook calls.

## 2026-09-27 - [CRITICAL] API Spoofing via Unauthenticated Telegram Callback ID
**Vulnerability:** The Telegram webhook handler was extracting `update.callback_query.id` from an unverified, user-supplied JSON payload and using it to call the Telegram API (`answerTelegramCallback`) when authentication failed. An attacker could supply an arbitrary callback ID belonging to another bot or context, forcing the server to make unauthorized outbound API calls to Telegram on their behalf (API Spoofing / Server-Side Request Forgery).
**Learning:** Never use unauthenticated user-supplied data (such as a Telegram `callback_query.id` from an unverified payload) to execute backend logic or make external API calls. This creates SSRF and API spoofing vulnerabilities, as the server can be tricked into interacting with external services using malicious input.
**Prevention:** Always verify the cryptographically secure webhook secret (e.g., `x-telegram-bot-api-secret-token`) *before* parsing the request body (e.g., `await request.json()`). Do not fall back to inspecting user-supplied payloads prior to validation, and never initiate API actions based on unverified data.
