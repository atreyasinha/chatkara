## 2025-02-18 - [CRITICAL] Telegram Webhook Authentication Bypass
**Vulnerability:** The Telegram webhook (`/api/telegram/webhook/route.ts`) verified requests by falling back to checking if the user-controlled JSON payload (`update?.callback_query?.message?.chat?.id`) matched an authorized `TELEGRAM_CHAT_ID` if the `TELEGRAM_WEBHOOK_SECRET` was missing or mismatched. Because webhooks are publicly accessible, an attacker could spoof this JSON payload to bypass authentication completely and update order states (e.g., mark as paid or cancelled).
**Learning:** Never use data from a user-supplied JSON payload as a fallback authentication mechanism for webhooks. Secrets should be enforced strictly.
**Prevention:** Always rely strictly on cryptographically secure tokens (like `x-telegram-bot-api-secret-token`) sent in headers and verified with a constant-time comparison (`timingSafeEqual`) to authenticate webhook calls.

## 2024-05-18 - Webhook Authentication Bypass in JSON Parsing
**Vulnerability:** The Telegram webhook endpoint (`src/app/api/telegram/webhook/route.ts`) attempted to parse the incoming request body (`request.json()`) *before* verifying the webhook secret token. Furthermore, if authentication failed, it fell back to invoking an external Telegram API call (`answerTelegramCallback`) using unauthenticated callback ID data extracted from the payload.
**Learning:** This exposes the application to unauthenticated payload processing and allows attackers to trigger external API requests using arbitrary data by supplying malicious JSON. Even if a request fails authentication, no untrusted input from the payload should be processed or relayed to external services.
**Prevention:** Always rely strictly on cryptographically secure tokens sent in headers and verified with a constant-time comparison (`timingSafeEqual`) to authenticate webhook calls, and perform this verification *before* parsing the JSON body or attempting to process any unverified input.
