## 2025-02-18 - [CRITICAL] Telegram Webhook Authentication Bypass
**Vulnerability:** The Telegram webhook (`/api/telegram/webhook/route.ts`) verified requests by falling back to checking if the user-controlled JSON payload (`update?.callback_query?.message?.chat?.id`) matched an authorized `TELEGRAM_CHAT_ID` if the `TELEGRAM_WEBHOOK_SECRET` was missing or mismatched. Because webhooks are publicly accessible, an attacker could spoof this JSON payload to bypass authentication completely and update order states (e.g., mark as paid or cancelled).
**Learning:** Never use data from a user-supplied JSON payload as a fallback authentication mechanism for webhooks. Secrets should be enforced strictly.
**Prevention:** Always rely strictly on cryptographically secure tokens (like `x-telegram-bot-api-secret-token`) sent in headers and verified with a constant-time comparison (`timingSafeEqual`) to authenticate webhook calls.

## 2025-02-18 - [CRITICAL] Prevent JSON Parsing DoS on Webhook
**Vulnerability:** The Telegram webhook route (`/api/telegram/webhook/route.ts`) previously parsed the request body (`await request.json()`) before validating the authentication secret (`verifyTelegramSecret(request)`). Because JSON parsing is CPU-intensive and blocks the event loop, an attacker could send maliciously large or complex JSON payloads to this unauthenticated endpoint, causing a Denial of Service (DoS) by exhausting server resources.
**Learning:** Authentication checks that rely on headers must always be performed *before* any payload parsing. Payload parsing should only occur for authenticated clients to minimize the attack surface.
**Prevention:** Always validate webhook secrets from headers (e.g., `x-telegram-bot-api-secret-token`) first, and immediately return a 401 Unauthorized status if missing or invalid, avoiding any `request.json()` or other payload inspection.
