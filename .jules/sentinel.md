## 2025-02-18 - [CRITICAL] Telegram Webhook Authentication Bypass
**Vulnerability:** The Telegram webhook (`/api/telegram/webhook/route.ts`) verified requests by falling back to checking if the user-controlled JSON payload (`update?.callback_query?.message?.chat?.id`) matched an authorized `TELEGRAM_CHAT_ID` if the `TELEGRAM_WEBHOOK_SECRET` was missing or mismatched. Because webhooks are publicly accessible, an attacker could spoof this JSON payload to bypass authentication completely and update order states (e.g., mark as paid or cancelled).
**Learning:** Never use data from a user-supplied JSON payload as a fallback authentication mechanism for webhooks. Secrets should be enforced strictly.
**Prevention:** Always rely strictly on cryptographically secure tokens (like `x-telegram-bot-api-secret-token`) sent in headers and verified with a constant-time comparison (`timingSafeEqual`) to authenticate webhook calls.

## 2025-02-18 - [CRITICAL] Unauthenticated Webhook Payload Parsing & SSRF Risk
**Vulnerability:** The Telegram webhook (`/api/telegram/webhook/route.ts`) parsed the JSON request payload before verifying the webhook secret. Worse, if verification failed, it used the unauthenticated `callback_query.id` from the payload to make an external API call (`answerTelegramCallback`) back to Telegram. This created a JSON parsing DoS vector and a Server-Side Request Forgery (SSRF) risk where an attacker could trick the server into sending authorized Telegram API requests using arbitrary, attacker-controlled callback IDs.
**Learning:** Parsing JSON payloads before authentication wastes server resources on unauthenticated data (DoS risk). Making external API calls or executing logic using unauthenticated user-supplied data introduces SSRF and other severe injection risks.
**Prevention:** Always verify cryptographic secrets (like `x-telegram-bot-api-secret-token`) *before* parsing the request body (`await request.json()`). Never fall back to inspecting or acting upon user-supplied payloads prior to validation, and immediately return 401 if authentication fails.
